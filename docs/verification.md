## 实际体验与修正

通过应用浏览器实际操作 Acme Studio 演示工作区：打开 APP-3、搜索负责人、变更并核对“林予安 → 陈念”历史、恢复负责人、打开 MDXEditor 检查清单/代码/工具栏，关闭详情并检查完整看板。

以 Jira 常见工作路径为对照，已修正：

- 卡片和元信息字号偏小；列独立滚动、固定列标题，空状态保留落点。
- 拖拽落区回跳；500 条事项下由布局测量触发的循环更新。
- 描述保存期间仍可输入造成内容丢失；冲突重提使用旧版本号；以编辑开始时的 Markdown 判断冲突。
- 字段编辑和拖拽使用统一 Issue 串行队列；回滚仅影响失败事项；创建/评论请求重试复用幂等键。
- 登录切换后的旧缓存、未登录工作区查询引发循环刷新、深链错误项目上下文。
- 默认当前 Sprint，并让新建事项继承当前状态/Sprint；连续创建恢复标题焦点。
- 可读关系快照、旧活动分页、描述版本入口；工作流设置历史。
- 只读角色的编辑控件、Sprint 删除确认、工作流改名/排序、项目成员移除和小屏导航。

## 500 条事项测量

使用独立项目直接插入 500 条事项；真实浏览器加载所有 500 张卡、拖拽并确认 API 返回和目标分区。没有把测试数据写入用户项目。

最终 Docker 生产构建结果：Board API 五次为 **32 / 27 / 23 / 33 / 27 ms**；从导航到 500 张卡出现 **1861 ms**；鼠标移动步骤加服务端确认 **829 ms**。最后一次开发构建回归为 35 / 30 / 26 / 30 / 25 ms，首次呈现 1735 ms，拖拽步骤加确认 3149 ms。

这些是本机端到端单轮记录，包含浏览器自动化输入时间，不等于逐帧响应或 SLA。测试保存 `test-results/` 下的截图和 JSON 指标。Board 当前上限 5000 条，不宣称超大项目性能已经验证。

## 仍需明确的边界

- 中文内容和 composition 保护代码已验证，**真实中文输入法候选窗操作尚未人工验收**；自动输入中文不能代替输入法验证。
- MDXEditor 首次编辑按需加载，完整编辑器包仍较大；后续可以按代码语言进一步减小首次加载。
- 当前工作区写命令串行锁适合小团队；未做高并发、多实例负载或长期运行验证。
- 会话草稿存于当前页面进程，刷新前提示；未做离线存储和跨设备草稿。
- 描述修订列表最近 100 个、评论最近 200 条；超长历史体验需后续扩展。普通活动支持游标分页。
- 没有真实 Jira 环境进行并排基准，比较基于其常见操作路径；不宣称完整 Jira 功能等价。
