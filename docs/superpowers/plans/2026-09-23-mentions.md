# Mentions and Notifications Implementation Plan

> Use superpowers:subagent-driven-development for independent backend/frontend tasks and final review.

**Goal:** Project members can mention colleagues in descriptions/comments and receive durable notifications through the app, email, with a provider interface for future Feishu integration.
**Architecture:** Standard Markdown links hold stable actor identity. Issue transactions enqueue notification events; a separate worker dispatches channel deliveries. UI shares mention selection and rendering.
**Tech Stack:** Existing React/MDXEditor/NestJS/Prisma/PostgreSQL; SMTP transport and Markdown AST parser where needed.
**Spec:** docs/superpowers/specs/2026-09-23-mentions-design.md

## Constraints and review focus

- No OSS implementation, no real test messages, credentials only deployment env.
- Actor IDs and current project access are authoritative; never trust display names.
- Exclude code examples and invalid links from mention extraction.
- Publish/transaction boundaries, duplicate save and conflicting versions must not spam.
- Worker rechecks membership and source cancellation; external delivery cannot promise exactly-once.
- Keyboard/IME and draft preservation stay intact.

## Tasks

- [x] Backend: add notification/outbox schema and migration, extraction and issue hooks; expose scoped recipients/inbox/read endpoints; SMTP adapter and future provider interface, worker and env/docs. Integration tests must cover scope, idempotency, source edits, retry and concurrent claims.
- [x] Frontend: description/create MDXEditor mention picker, comment mention picker and rendering; notification bell/list/read with deep links. Browser tests cover actual saves and read flow.
- [x] Independent review across schema, permissions, parsing, worker and editor; resolve concrete findings.
- [x] Full lint/format/types/unit/integration/build, production preview and browser regression; document provider configuration limits, commit and push.

## Implementation rulings

- Removed mentions retract inbox reminders, including read reminders, so the inbox points to current actionable mentions. Sent mail cannot be recalled; original history remains in issue revisions/activity. This makes existing cancellation behavior explicit.
