# GitHub Integration Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development to implement and review bounded tasks.

**Goal:** Deliver GitHub App repository binding, PR/commit links, webhook synchronization and conservative configurable automation.
**Architecture:** Nest GitHub module + Prisma persistent sync data; shared authorized API; React settings and Development sections.
**Tech Stack:** Existing TypeScript/Nest/Prisma/PostgreSQL/React; native crypto/fetch.
**Spec:** docs/superpowers/specs/2026-09-23-github-design.md

- [x] Backend: schema/migration, App API client, DTO/controllers, durable webhook worker, association and automation transaction. Integration tests cover boundaries with mocked external API.
- [x] UI: GitHubSettings and IssueDevelopment, shared contracts, settings and drawer integration; no secrets in UI; loading/error/empty states, configurable rules.
- [x] Review: inspect permissions, signature, retries/leases, event ordering and UI. Fix findings.
- [x] Validate: migration/generate, lint/format/typecheck/unit/integration/build; browser interaction; update owned Docker preview. Document setup/limitations. Commit and push per standing authorization.

Ruling: GitHub App installation credentials are deployment settings, administrators bind authorized installation IDs; no OAuth needed. Initial import does not change statuses. Current preview stays at the existing checkout to preserve running development context.

Ruling: 用户明确不考虑无 hook 情况，取消定时 GitHub 轮询，仅保留 Webhook 和手动补同步。评审发现并修复同步队列丢更新、多仓库延迟合并、限流退避、PR 评审/打开并发事件和重试按钮状态问题。仓库用不可变 ID 解析规范名称，待执行规则重放在事务中重新验证同步状态。
