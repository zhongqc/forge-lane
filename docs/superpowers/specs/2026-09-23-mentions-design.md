# @ 提及与通知设计

用户要求实现 @ 提及，通知可通过邮件，并支持飞书等第三方。沿用用户此前直接执行授权；OSS 图片/附件仍然暂缓。此次只通知新提及，不扩展到所有事项变更。

## 交互与内容

描述（含创建）和评论支持输入 @ 搜索当前项目可访问成员，键盘上下选择、Enter 选中、Escape 关闭，尊重中文输入法。保存普通 Markdown 链接 `[@显示名](/mentions/ACTOR_UUID)`，稳定 Actor ID 是身份依据；纯文本 @姓名不发送。显示名称转义，重名成员可辨识。阅读模式用提及样式显示，不跳转无效页面。代码块/行内代码中的示例不是提及。

描述保存、评论发布/编辑成功后，仅通知相较上一版新增的合法成员，一人一次；不通知自己。事务内创建持久通知；回滚、版本冲突、幂等重试不重复产生通知。删除评论/移除提及会撤回对应站内提醒，并取消尚未发送的邮件；已发邮件无法撤回，原始内容历史仍保留在事项活动和修订中。再次添加可产生新的事件。CLI/API 使用相同 Markdown 格式，同样生效。

## 通知与权限

持久通知为真实发送者、收件人、项目、事项、来源（描述/评论）、来源版本及时间。收件人查看自己的站内列表与未读数，点击跳转事项，可标记已读。权限在生成和投递时校验；失去项目访问权后不显示内容且不投递。项目成员候选不泄漏跨项目身份。

邮件通过部署 SMTP 配置；渠道接口隔离业务事件与发送。用户已确认：本次先实现邮件，飞书仅预留渠道接口，不实现真实飞书投递或账号绑定。配置不存在时不伪装发送成功，站内通知仍可用。密钥只在部署环境，前端不读取；本次测试仅使用模拟渠道，不向真实用户发送测试消息。

通知发送通过数据库 outbox 与 worker，领取锁/租约防止并行重复执行，有限重试与可诊断的失败状态。外部邮件不保证 exactly-once，明确可能存在“已发送但确认丢失”的重复；事件与渠道唯一键防止正常重复投递。发送内容精简为提及人、事项编号/标题、跳转链接，不直接发送完整需求或评论正文。未配置渠道不启动外部发送。

## 验证

解析普通 Markdown、排除代码、重复和伪造成员、自己、跨项目、成员撤销、创建和编辑增量、取消未发送、幂等冲突；worker 失败重试和并发；UI 创建/描述/评论 @ 选择、中文输入保护、键盘、保存重开、通知入口。真实供应商投递待部署配置后验收。
